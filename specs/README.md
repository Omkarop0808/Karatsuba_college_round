# Verity — Prove the Computation, Not Just the Result

**BitNBuild hackathon project for `ps.md` (blockchain-based verifiable computation).**
All planning and specification documentation lives in this `specs/` folder.

## Concise Project Summary

Organizations outsource heavy computations (risk scoring, AI inference, audits) to external
providers, then face a dilemma: **blindly trust the result, or wastefully re-run the whole
computation locally.** Verity removes the dilemma. A requester posts a task on-chain with locked
bounty escrow; a worker executes the computation off-chain and submits the result **with a real
Groth16 zk-SNARK proof (Circom + snarkjs, BN254)**; the EVM verifies the proof on-chain in
constant gas via the `ecPairing` precompile (`0x08`). Valid proofs finalize and pay out.
Invalid proofs revert. Bonded challengers can dispute during a challenge window, with slashing
for liars on either side. A built-in **Chaos Lab** lets judges fire 4 live attacks and watch the
contracts reject each one, and every finalized task mints a tamper-evident **Proof Passport**
with full execution lineage.

## Locked Architecture Decisions

| Decision | Choice |
|---|---|
| Proof system | Real Circom 2.1 + Groth16 (BN254), Solidity verifier auto-generated by snarkjs |
| On-chain verification | True pairing check via EVM precompile `0x08` (not a signature attestation) |
| Scope | Full 5-phase build: contracts + proving pipeline + worker + web + Chaos Lab + Passport |
| Chain target | Local Anvil by default; Base/Arbitrum Sepolia optional |
| Specs folder | `specs/` |

## Quick Orientation for the Implementer

1. Read `PRD.md` → `TECH-SPEC.md` → `WORKFLOW.md` → `STACK.md` → `IMPLEMENTATION-PLAN.md`.
2. Install prerequisites in `STACK.md` (Foundry + Circom might not yet be installed).
3. Execute phases in order; every phase has a verifiable exit criterion. Never claim a phase
   done without the evidence its exit criterion demands.
